# Luminair API Reference & Canonical Error Schema

- **Audience**: Backend developers, API consumers, frontend engineers (Admin Studio), SDK authors
- **Governing RFCs**: [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) (Problem Details for HTTP APIs, obsoletes RFC 7807)
- **Code implementation**: [`application::errors`](../application/src/errors.rs) (`ApplicationError`, `ConflictCode`, `ProblemDetails`)
- **Last reviewed**: 2026-10-22

---

## 1. Architectural Philosophy

Luminair decouples **machine-readable API error reporting** from **end-user human localization**:
1. **The Backend Never Guesses User Copy**: The backend returns a stable, machine-readable `code` and structured metadata parameters in `details`. It provides a default English `detail` message strictly for developer debugging in terminals, logs, and curl.
2. **Third-Party Integrations Are Safe & Reliable**: API clients, services, and SDKs programmatically branch on `code` (e.g. `if error.code == "draft_has_pending_edits"`), eliminating fragile regex or substring matching on English sentences.
3. **The Frontend Owns Localization (i18n)**: The UI client (Admin Studio or customer frontend) knows the user's active locale and formatting preferences. It maps `code` to its own localized translation dictionary (`t('errors.' + error.code, error.details)`) and can render rich interactive dialogs (e.g. confirmation modals with action buttons).

## 2. Canonical API Error Schema (RFC 9457)

All non-2xx responses from Luminair HTTP endpoints return `Content-Type: application/problem+json` formatted according to RFC 9457 Problem Details:

```json
{
  "type": "urn:luminair:error:draft_has_pending_edits",
  "title": "Conflict",
  "status": 409,
  "code": "draft_has_pending_edits",
  "detail": "Restoring snapshot would overwrite pending working draft edits; confirm with discard_pending_edits: true",
  "instance": "/api/v1/content/articles/01946890-7812-789a-bcde-000000000001/snapshots/1/restore",
  "details": {
    "document_id": "01946890-7812-789a-bcde-000000000001",
    "target_revision": 1,
    "draft_version": 3
  }
}
```

### Schema Properties

| Field | Type | Required | Description |
|---|---|---|---|
| `type` | String (URI) | Yes | Canonical URI identifying the problem type: `urn:luminair:error:<code_name>`. |
| `title` | String | Yes | Short, human-readable summary of the problem type (e.g. `"Conflict"`, `"Not Found"`, `"Forbidden"`). |
| `status` | Integer | Yes | The HTTP status code generated by the origin server for this occurrence. |
| `code` | String | Yes | **Primary machine-readable discriminator**. Stable `snake_case` identifier used by SDKs for branching and by UIs for i18n lookup. |
| `detail` | String | Yes | Human-readable diagnostic explanation of this specific occurrence (English fallback for developers/logs). |
| `instance` | String (URI) | No | URI reference that identifies the specific occurrence of the problem (endpoint path). |
| `details` | Object | No | Key-value object containing contextual machine-readable parameters for client-side interpolation and automated handling. |
| `invalid_params` | Array | No | Detailed field-level errors for validation failures (`422 Unprocessable Entity`). |

### Field-Level Validation Format (`invalid_params`)

When `code` is `"validation_failed"`, the payload includes `invalid_params`:

```json
{
  "type": "urn:luminair:error:validation_failed",
  "title": "Unprocessable Entity",
  "status": 422,
  "code": "validation_failed",
  "detail": "title must not be empty; body locale 'fr' unknown",
  "invalid_params": [
    {
      "name": "title",
      "reason": "field is required and cannot be empty",
      "code": "required_field_missing"
    },
    {
      "name": "body",
      "reason": "locale 'fr' is not configured in system locales",
      "code": "unknown_locale"
    }
  ]
}
```

## 3. Standard Error Code Catalog

### 3.1 Conflict Errors (`409 Conflict`)

Conflict errors occur when the requested command is valid in isolation but conflicts with existing system or document lifecycle state.

| `code` | Meaning / Trigger | `details` Payload | Resolution Strategy |
|---|---|---|---|
| `draft_has_pending_edits` | Calling `restore_snapshot` on a document in `Modified` state without `discard_pending_edits: true`. | `{"document_id": UUID, "target_revision": int, "draft_version": int}` | Prompt user to confirm discarding uncommitted edits, then retry with `discard_pending_edits: true`. |
| `already_published` | Calling `publish` on a clean `Published` document that has no pending working draft edits (`DS-17`). | `{"document_id": UUID}` | Do not re-publish. The document is already live with identical content. |
| `draft_and_publish_disabled` | Calling `publish` or `unpublish` on a document type with `draft_and_publish: false` (`DS-07`). | `{"document_type": string}` | Single-lifecycle documents are updated directly via `PUT /api/v1/content/:type/:id` without explicit publication. |
| `version_mismatch` | Optimistic Concurrency Control failure: document version in database does not match `expected_version`. | `{"expected_version": int, "found_version": int}` | Re-fetch the latest document state (`GET ...?view=working`), resolve diffs, and retry. |
| `single_type_already_exists` | Calling `create` on a `Singleton` document type when an instance already exists. | `{"document_type_id": string}` | Use `PUT` to update the existing singleton instance. |
| `access_request_already_active` | User submitted an access request while an active request is already pending. | `{"user_id": string}` | Await review of the existing pending request. |
| `user_already_enrolled` | User submitted an access request but already has active roles in the system. | `{"user_id": string}` | Log in directly; user is already provisioned. |

### 3.2 Not Found Errors (`404 Not Found`)

| `code` | Meaning / Trigger | `details` Payload |
|---|---|---|
| `resource_not_found` | Generic entity not found. | `{"entity": string, "id": string}` |
| `document_type_not_found` | Target document type is not declared in the schema registry. | `{"document_type_id": string}` |
| `document_instance_not_found` | Document ID does not exist in the requested view (`working` vs `published`). | `{"document_instance_id": UUID, "view": string}` |
| `access_request_not_found` | Access request ID was not found during approval or rejection. | `{"access_request_id": UUID}` |

### 3.3 Authorization & Onboarding Errors (`401 Unauthorized` / `403 Forbidden`)

| `code` | Status | Meaning / Trigger | `details` Payload | UI Action |
|---|---|---|---|---|
| `unauthorized` | 403 | Caller lacks required RBAC permission or resource ownership. | `{"actor": string, "action": string}` | Display access denied banner. |
| `access_not_requested` | 403 | Authenticated user has no assigned roles and has not submitted an access request. | `{"user_id": string}` | Redirect to Onboarding / Access Request Form. |
| `access_pending` | 403 | Authenticated user has a pending access request awaiting administrator review. | `{"user_id": string, "submitted_at": string}` | Show pending notification with status auto-polling. |
| `access_rejected` | 403 | User's access request was rejected. | `{"user_id": string, "reason": string}` | Display rejection notice with re-submit option. |

### 3.4 Validation Errors (`422 Unprocessable Entity`)

| `code` | Meaning / Trigger | `details` Payload |
|---|---|---|
| `validation_failed` | Input entity failed schema validation rules. | `{"invalid_params": [...]}` |
| `invalid_field_value` | Attribute value violates type matching, regex, bounds, or required constraint. | `{"attribute_id": string}` |
| `unknown_attribute` | Payload contains an attribute not declared in the schema. | `{"attribute_id": string}` |
| `unknown_locale` | Field value references a locale not supported by system configuration. | `{"locale": string}` |
| `invalid_state_transition` | Operation is illegal for current state (e.g. unpublishing a draft). | `{"reason": string}` |
| `invalid_schema_display_field` | Schema definition violates display field limits (max 3, max 1 relation). | `{"type_id": string}` |

### 3.5 System & Persistence Errors (`500 Internal Server Error`)

| `code` | Meaning / Trigger |
|---|---|
| `storage_error` | Database query failure, serialization error, or lock poison. |
| `internal_error` | Unexpected internal server failure. |

## 4. Guide for API Developers (Third-Party & Services)

When building services or CLI tools integrating with Luminair:

1. **Always inspect `error.code`**:
   ```typescript
   try {
     await luminair.restoreSnapshot(docId, revision);
   } catch (err: any) {
     if (err.response?.data?.code === "draft_has_pending_edits") {
       // Ask user or enforce override
       await luminair.restoreSnapshot(docId, revision, { discardPendingEdits: true });
     } else {
       throw err;
     }
   }
   ```

2. **Handle Optimistic Concurrency Control (`version_mismatch`)**:
   ```typescript
   if (err.response?.data?.code === "version_mismatch") {
     const latest = await luminair.getWorkingDraft(docId);
     // Merge changes and retry with latest.audit.version
   }
   ```

3. **Never parse English strings**: Do not perform regex checks like `/already published/i` or `/overwrite pending/i`. The human `detail` text is subject to refinement, whereas `code` is a permanent contract.

## 5. Guide for Frontend Developers (Admin Studio & Localization)

### 5.1 Mapping Error Codes to Localized Strings

The Admin Studio UI maintains translation catalogs keyed by error code:

```typescript
// frontend/src/utils/errors.ts
import { useTranslation } from "react-i18next";
import { ProblemDetails } from "../types/errors";

export function getLocalizedErrorMessage(t: (key: string, opt?: any) => string, error: ProblemDetails): string {
  const i18nKey = `errors.${error.code}`;
  
  // Check if a translation exists for this specific error code
  if (i18n.exists(i18nKey)) {
    return t(i18nKey, error.details || {});
  }
  
  // Fallback to backend debug detail
  return error.detail || t("errors.unknown_error");
}
```

### 5.3 Interactive Dialog Handling

For errors that represent a recoverable decision (such as `draft_has_pending_edits`), the UI intercepts the error code and opens an interactive confirmation modal:

```typescript
// Inside Admin Studio Mutation Error Handler
if (error.code === "draft_has_pending_edits") {
  modals.openConfirmModal({
    title: t("modals.overwrite_draft_title"),
    children: (
      <Text size="sm">
        {t("errors.draft_has_pending_edits", error.details)}
      </Text>
    ),
    labels: { confirm: t("common.discard_and_restore"), cancel: t("common.cancel") },
    confirmProps: { color: "red" },
    onConfirm: () => restoreSnapshotMutation.mutate({ ...params, discardPendingEdits: true }),
  });
}
```

## 6. Core REST API Endpoints Overview

All endpoints accept and return JSON. Authenticate requests using `Authorization: Bearer <JWT>`.

### 6.1 Content Management Endpoints

| Method | Path | Description | Version View |
|---|---|---|---|
| `GET` | `/api/v1/content/:type_id` | Query published documents (visitor view). | `Published` |
| `GET` | `/api/v1/content/:type_id/admin/headers` | Lightweight Admin Studio projection across all statuses. | Mixed (`DocumentHeader`) |
| `GET` | `/api/v1/content/:type_id/:id` | Get document by ID with query parameter `?view=published` (default) or `?view=working`. | `Published` / `Working` |
| `POST` | `/api/v1/content/:type_id` | Create document instance (creates draft or publishes if `draft_and_publish: false`). | `Draft` or `Published` |
| `PUT` | `/api/v1/content/:type_id/:id` | Update document instance (edits draft, transitions `Published` $\rightarrow$ `Modified`). | `Working` |
| `DELETE` | `/api/v1/content/:type_id/:id` | Delete document instance (moves to trash tombstones per ADR-005). | Removed |
| `POST` | `/api/v1/content/:type_id/:id/publish` | Publish working draft to live wide table. | `Published` |
| `POST` | `/api/v1/content/:type_id/:id/unpublish` | Take published document offline (body accepts `draft_resolution: "keep_draft" \| "replace_with_published"`). | `Unpublished` |
| `POST` | `/api/v1/content/:type_id/:id/discard-draft` | Discard pending working draft edits and revert to clean live published state. | `Published` |
| `GET` | `/api/v1/content/:type_id/:id/snapshots` | List revision snapshot history headers. | Archive (`SnapshotHeader`) |
| `GET` | `/api/v1/content/:type_id/:id/snapshots/:revision` | Inspect full historical revision content and relations. | Archive (`DocumentSnapshot`) |
| `POST` | `/api/v1/content/:type_id/:id/snapshots/:revision/restore` | Restore historical revision into working draft (body: `{"discard_pending_edits": bool}`). | `Modified` |

### 6.2 Authentication & Access Requests

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/v1/auth/access-requests` | Submit an access request for onboarding. |
| `GET` | `/api/v1/auth/access-requests` | List pending access requests awaiting review (admin only). |
| `GET` | `/api/v1/auth/access-requests/:id` | Get access request status (owner or admin). |
| `POST` | `/api/v1/auth/access-requests/:id/approve` | Approve access request and assign roles (admin only). |
| `POST` | `/api/v1/auth/access-requests/:id/reject` | Reject access request with reason (admin only). |

### 6.3 System Configuration

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/v1/system/config` | Get system configuration (default locale, active locales). |

### 6.4 Schema & Content Types

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/v1/schema/document-types` | List all registered document types and schemas. |
| `GET` | `/api/v1/schema/document-types/:id` | Get schema definition for a specific document type. |
